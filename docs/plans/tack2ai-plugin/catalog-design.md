# 源点动力统一模型接入设计

输入：[统一模型接入需求](catalog-requirements.md)。现有后台先预览模型 ID、再导入所选 ID；源点动力网关已提供按 Key 隔离的 `GET /v1/catalog/models`。沿用同一渠道地址及四个协议 ID，不新增按模型名匹配的规则。

## 方案及取舍

- 只改安装包：能补生成请求字段，但不能让后台按 Key 读目录并预填能力，新模型继续依赖人工选协议。
- 插件加后台导入（已选）：在后台现有拉取/确认流程增加源点动力目录解析和能力预填，插件仍只负责把已校验的生成请求编码成统一出口的请求。网关不变，插件版本仍是 `1.0.0`。

## 设计决策

- DD-01（AC-01）：只在渠道为 OpenAI 且确认是官方 HTTPS 地址 `ai.tack2ai.cn` 时，走源点动力目录分支；其他地址走原有发现流程。请求固定到同源目录路径，凭据用服务端已有渠道 Key，经现有出站校验、响应限制和请求取消机制。不按目录返回值拼接地址或追加请求头，不在鉴权失败时回退到公开目录。
- DD-02（AC-02、AC-04）：用目录声明的能力、端点、参数和素材限制生成一个类型化预览。只识别当前插件支持的组合；缺少判定依据、多能力无法选定、参数存在冲突时给出原因。读取和导入共用解析规则；预览返回与渠道和模型绑定的配置指纹，确认导入时重取目录并比对所选模型的指纹。只使用服务端重新校验后的配置写入，不采信客户端回传的能力和价格。已有条目、已合并 SKU 和其他渠道继续执行原规则。
- DD-03（AC-03）：插件沿用 `tack2ai-chat/image/video/audio`。独立处理两种图片尺寸合同：像素尺寸，或档位加比例；视频仅映射统一出口支持的固定时长、分辨率、比例、参考素材和明确支持的扩展；语音仅在有效音色已声明或显式选择时发送，并按能力与宿主素材支持决定是否发送参考素材。核对语音模型能力持久化、前端默认音色和后台测试调用链，避免宿主在插件编码前注入 `alloy`；不改变其他语音协议的默认值。参数必须由已知协议白名单与模型声明共同约束，不能把上游目录 JSON 直接当作请求体。既有视频恢复、鉴权下载、错误语义和不重投保持不变。
- DD-04（AC-04）：后台明确区分可预填、需补能力、目前不支持；不把「已导入」描述成「可收费调用」。新增条目不写价格并保持停用。成本与售价由管理员核对；动态报价或不能表达的账单规则保留限制说明，不生成猜测价。本次不改变其他渠道的启停和计费规则，已导入模型的后续能力变化也不被定期覆盖。
- DD-05（AC-05）：覆盖陌生模型 ID、两种图片尺寸、视频查询与参考素材、语音输入与音色、目录返回错误、模型从列表消失、已存在条目和旧渠道维持原行为。使用模拟上游，不启用真实模型。打包前先记录原包 SHA256，保留恢复依据，并验证最终 ZIP 与源码一致。

实施约束：按模态、操作和端点共同判断协议；通用 `openai` 标签不足以区分 TTS 和转写。保留网关模型 ID 原值；归一化后发生重复时标记冲突，不静默覆盖。保留已有图片像素字段的编码，档位与独立比例仅在明确配置时生效，避免旧模型无改动却出现新选项。

## 文件边界

插件清单、说明、安装包及其测试；影策后台现有渠道目录导入服务、必要的管理 API 和「拉取模型」对话框；同步相关接口说明和待验收项。复用现有模型及能力配置，不加表或迁移，不改网关、不引入依赖。

## 失败与回退

目录请求或校验失败不写配置；导入前发现关键能力变化，返回原因让管理员重新拉取确认；不能识别的模型保持不可导入或不可启用，不以默认能力或零价绕过。需要回退时恢复原包和本次宿主差异，不删除用户已有渠道或历史账单。
